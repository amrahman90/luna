# Work Queue 03 — Per-DTM Floors + Candidate Extraction at N=51

**Priority:** 4
**Wall time:** ~2 hours (mostly I/O; the score rasters are cached
from #1)
**Cost:** $0 (compute-only; no new egress)
**Pre-req:** work-queue #1 complete (30 DTMs cached) + the existing
21 from G2 = N=51.

## Task

Re-run the per-DTM noise floors + candidate extraction at the full
N=51 set (currently N=21 at G2; adding the 30 from #1 brings the
total to N=51 — the first honestly-survey-scale candidate set in
LUNARVOID).

The G2 verdict (`plans/2026-08-23_GATE_G2_report_v1.0.md`) was
PARTIAL: N=21 is still a calibration-context sample, not a survey
rate. N=51 is the next step that begins to look like a survey rate
(though still small for a 649-DTM population).

## Steps

1. SSH to the Hetzner server.
2. Run the per-DTM floor aggregator:
   ```
   /opt/lunarvoid/venv/bin/python \
       /opt/lunarvoid/repo/01_WORKSPACE/code/wp0_kriging/per_dtm_floors.py \
       --dtms-from-registry
   ```
   This re-aggregates `per_dtm_floors.csv` over the 51 DTMs.
3. Run the candidate extraction at N=51:
   ```
   /opt/lunarvoid/venv/bin/python \
       /opt/lunarvoid/repo/01_WORKSPACE/code/wp2_sag/transfer/transfer_apply.py \
       --all-51-dtms
   ```
4. Compute the aggregate FP rate per 10^4 km² over the N=51 area
   (target: 24,062 + 9,000-12,000 km² from #1 ≈ 33,000-36,000 km²
   total).
5. Report the per-DTM FPs, the aggregate FP rate with Poisson CI,
   and the FP-rate dilution argument (G1 §3 row 10).
