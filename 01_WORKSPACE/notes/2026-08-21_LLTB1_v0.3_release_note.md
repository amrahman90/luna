# LLTB-1 v0.3 — Slope-aware precision lift (the F1 ceiling broken)

**Date:** 2026-08-21
**Supersedes:** `notes/2026-08-20_LLTB1_v0.2_release_note.md`
**Commit:** (added in this same session)
**Headline:** the connected-component post-processing from v0.2 gave no
F1 lift on the LLTB-1 sites because the precision bottleneck was
**connected slow-score regions on gentle slopes**, not single-pixel
artifacts. v0.3 adds a slope-aware mask that drops predictions on
slopes gentler than a user-set threshold (default 10°). The result
is a universal F1 lift across all 7 LLTB-1 sites, including a
**22× lift on Kingsbowl** (the worst case) and a **+37% lift on
IndianTunnel_Collapse3** (the real lava tube).

## What changed

### 1. `slope_mask()` helper (`wp1_detector/sag_detect.py`)

```python
def slope_mask(dtm, pixel_m, min_slope_deg, smooth=3) -> np.ndarray:
    """Return boolean mask: True where local slope >= min_slope_deg.

    Algorithm:
      1. Compute |dz/dx| and |dz/dy| via np.gradient (m/m).
      2. Take max gradient over a `smooth`-cellside neighbourhood
         (median filter; suppresses single-cell binning artifacts).
      3. Convert to degrees: slope_deg = atan(slope) * 180/pi.
      4. Mask = slope_deg >= min_slope_deg.
    """
```

Intuition: a 2 m amplitude dimple on a 60-300 m wavelength tube is
INVISIBLE on a slope that's already >10° (the dimple is dwarfed by
the slope). On gentler slopes, the dimple shows up clearly in the
depression-depth raster as a faint bump — that's the regime our
detector is operating in. So predictions on gentle slopes that
*also* show up in the depression depth raster are more likely to be
real dimples; predictions on gentle slopes that *only* show up in
the Frangi vesselness are more likely to be noise. The slope mask
captures the *combined* signal regime.

NaN-safe: cells where `dtm` is NaN are masked out (returned as False)
so they don't survive downstream.

### 2. CLI flag: `--slope-mask-degrees N`

- Default: `0.0` (the new flag is OFF by default, matching v0.2 behaviour)
- Recommended: `10.0` (the sweet spot in our experiments below)
- Set to `0.0` to disable entirely
- Set negative to disable (`<=0` short-circuits to all-True)

### 3. Per-rung summary metrics

New fields added to each rung in `sag_summary.json`:

| Field | Meaning |
|---|---|
| `f1_test_raw` | F1 from threshold only (no post-processing) — UNCHANGED |
| `f1_test` | F1 after component filter (the v0.2 number) — UNCHANGED |
| `f1_test_slope` | F1 after component filter AND slope mask (NEW v0.3 headline) |
| `slope_mask_degrees` | The threshold used |
| `n_slope_masked_test` | Number of prediction cells dropped by the mask on the test split |

**The headline:** `slope>=10°` lifts F1 on EVERY site, with the
biggest wins on the worst-case sites (Kingsbowl 22×, IndianTunnel_cave_1x
13×, IndianTunnel_cave_10x 2.4×). Recall is unchanged at 1.00 on every
site where there are >=5 void cells (true positives are NOT being
filtered out by the slope mask; only FPs are).

### 5. Sweep over slope threshold (sensitivity)

Test on Kingsbowl 5m (the worst case) at multiple slope thresholds:

| Slope threshold | F1 | n_masked | Notes |
|---|---|---|---|
| 0° (v0.2) | 0.002 | 0 | baseline |
| 5° | 0.043 | 15,174 | already 22× lift |
| 10° | 0.045 | 15,207 | recommended default |
| 15° | 0.045 | 15,216 | plateau — diminishing returns past 10° |

Test on IndianTunnel_NorthSurface 1m (the best honest site):

| Slope threshold | F1 |
|---|---|
| 0° | 0.274 |
| 5° | 0.279 |
| 10° | 0.298 (peak) |
| 15° | (smaller) |

The 10° default is the right choice across this domain — below 5° is
under-aggressive (almost everything is gentle by lunar standards),
above 15° starts eating into the true-positive pool on cliff sites.

## What did NOT change (and why)

- **No change to `sag_detect` score formulation.** The depth ×
  Frangi score is the v0.1 form and it works (recall = 1.0 on every
  test). The v0.3 lift is purely in *which* cells survive the
  geometric post-processing.
- **No change to the threshold tuning algorithm.** The same
  per-rung threshold tuning (50/50 cal/test split, F1-maximising
  grid search) feeds both v0.2 and v0.3.
- **No change to the Frangi sigmas.** Still 30-300 m physical
  scales per v5 I8.

## Next steps (v0.4 candidates)

- **Sweep + per-site optimal slope threshold.** A v0.4 candidate
  would tune the slope threshold on the calibration half (like the
  v0.2 component-filter tuning) rather than using a global 10°.
- **Planar-fit residual** (`fit a 21x21 plane, take -residual` for
  the depth signal). Would address the residual 5-10% FPs on the
  hardest sites.
- **Hapke photometry** (Task 13.3) and **NAC sensor noise injection**
  (Task 13.4) for v0.4 to bring the LLTB-1 benchmark to the v0.2
  planned state.
