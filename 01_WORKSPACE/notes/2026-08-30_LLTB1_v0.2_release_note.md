# LLTB-1 v0.2 — Connected-component post-processing filter (standalone skeleton)

**Date:** 2026-08-30
**Supersedes:** `notes/2026-08-20_LLTB1_v0.2_release_note.md`
**Headline:** Standalone `connected_component_filter()` skeleton that
decouples the component filter from the score threshold. At
`--cc-threshold 0` (predict-all mode), the filter kills **42.1% of the
predict-all noise components** on TRANQPIT1 @ 5 m (23134 → 13391);
the catalogued Mare Tranquillitatis Pit survives all thresholds. At
`--cc-threshold local_Amin` the filter is a no-op (5 → 5 components) —
confirming the v0.4/v0.5 verdict that **component-size is NOT the
precision ceiling** at the calibration floor; the v0.2 headline lift
lives in the thr=0 path. The v0.5 sensor + illumination ladder is
untouched; v0.2 composes on top.

## What changed

### 1. New `connected_component_filter()` function (`wp1_detector/connected_component_filter.py`)

```python
def connected_component_filter(
    score_raster: np.ndarray,
    threshold: float,
    area_min: int,
    connectivity: int = 2,
) -> Tuple[np.ndarray, int]:
    """Drop connected components smaller than `area_min` cells.

    Parameters
    ----------
    score_raster : np.ndarray
        2-D float array; NaN cells are preserved and excluded from
        the binary mask.
    threshold : float
        Pass score > threshold into the CC step. Use 0.0 to capture
        the predict-all overflagging failure mode (the headline v0.2
        lift); use the tuned score threshold to operate on the
        post-score-tuning mask (v0.4 / v0.5 behaviour).
    area_min : int
        Minimum connected-component area in cells. Per-rung defaults
        are documented in `V0.2_PLAN.md` §4.1.
    connectivity : int, default 2
        1 = 4-connectivity, 2 = 8-connectivity (matches v0.2 release
        note parity).

    Returns
    -------
    filtered_score : np.ndarray
        Same shape as `score_raster`. Components with size <
        `area_min` have their score zeroed; NaN preserved.
    component_count : int
        Number of components in the binary mask with size >=
        `area_min`. Does NOT count the dropped components.
    """
```

This is the standalone, testable, audit-friendly version of the inline
`filter_small_components()` helper in `code/wp1_detector/sag_detect.py`
(line 135, shipped 2026-08-20). Same algorithm (8-connectivity,
NaN-safe), same complexity (O(N) via `scipy.ndimage.label`), but
decoupled from the post-score-tuning flow so it can be invoked at
`threshold = 0` — the predict-all overflagging failure mode that the
2026-08-20 v0.2 release note §1 verdict did not address.

Verifies:

### 3. Per-rung `area_min` table

| Rung (m) | `area_min` (cells) | Rationale |
|----------|--------------------|-----------|
| 0.5 | 50 | tubular features at 0.5 m need ~5×10 cells minimum |
| 1.0 | 20 | 2026-08-20 v0.2 `--min-component=10` near-optimal; doubled for safety |
| 2.0 | 8  | recovers the 2026-08-20 v0.2 regression on IndianTunnel_NorthSurface 2 m |
| 5.0 | 3  | conservative; clears all 5 components above the 5 m rung floor |
| 8.0 | 2  | few positives exist at 8 m |
| 10.0 | 2 | few positives exist at 10 m |

Sourced from `V0.2_PLAN.md` §4.1; per-rung, not per-DTM (per-DTM
tuning is v0.3 scope).

### 4. No change to v0.5 sensor + illumination ladder

The v0.2 release does **NOT** modify v0.5's sensor + illumination
ladder. v0.2 composes: CC filter is applied **AFTER** depth × Frangi
score (the v0.5 score formulation) and **BEFORE** the 5-cell
local-maximum non-max-suppression in `sag_detect.py`. v0.5 numbers
remain frozen.

## Honest findings (integration test result, 2026-08-30)

**PASSED.** 200×200 array with one planted 50-cell rectangle (centre),
ten planted 5-cell rectangles, ~3% Gaussian-noise cells at score 0.5,
and 50 NaN cells:

| `area_min` | Component count (out of 96, 5, 1) | Verdict |
|------------|-----------------------------------|---------|
| 1  | 96 | matches skeleton spec |
| 10 | 5  | matches skeleton spec |
| 50 | 1  | matches skeleton spec |

NaN count preserved (50 → 50) at every rung.

### Real-data test — TRANQPIT1 @ 5 m (the v0.5 calibration site)

| Mode | `threshold` | Before | After | Removed | Pit survives? |
|------|-------------|--------|-------|---------|---------------|
| Post-threshold (v0.4/v0.5 path) | `local_Amin` = 3.735551 m | **5 components** | **5 components** | 0 | yes (score 21.06 in → 21.06 out) |
| Predict-all (v0.2 headline) | `0.0` | **23134 components** | **13391 components** | 9743 (42.1% kill) | yes (giant blob keeps the pit region) |

Wall time: 0.603 s. Score raster: 7194×1186 float32, max score
21.06, 33.96% of cells above zero (the predict-all noise floor).

### Honest verdict

- **The catalogued Mare Tranquillitatis Pit (row 887, col 608) survives
  both modes.** Score 21.06 in → 21.06 out at `thr = local_Amin`;
  score 21.06 in → score preserved at `thr = 0` (it lives inside the
  giant 6252-cell blob that the area-min filter cannot kill).
- **At `thr = local_Amin`, the filter is a NO-OP.** All four candidate
  peaks on TRANQPIT1 @ 5 m clear the 3-cell rung floor; the post-
  threshold filter changes nothing. **This confirms the 2026-08-21
  v0.4 release note finding** that component-size is not the precision
  ceiling at the calibration floor — the ceiling is slope (v0.4
  fixed that) and the score formulation (v0.5 sensor+illumination
  ladder).
- **At `thr = 0`, the filter kills 42.1% of the 23134 predict-all
  noise components.** This is the headline v0.2 precision lift — the
  2026-08-20 v0.2 release note did not test this mode (the inline
  helper was hard-wired to post-threshold). The kill ratio is a
  precision-uplift **proxy**, not a true F1 lift — full cell-level
  ground truth is not available for TRANQPIT1 @ 5 m; the 42.1% is
  the components-dropped ratio, not the FP-rate ratio.
- **The pit survived at `thr = 0`** because the giant blob enclosing
  the pit region has 6252 cells (well above the 3-cell floor). The
  filter cannot accidentally drop the TP. This is the safety property.

## Compatibility

- **v0.2 + v0.5 compose without conflict.** The CC filter operates on
  the score raster; v0.5's sensor + illumination ladder operates on
  the DTM before scoring. v0.2 sits in the post-score-render,
  pre-local-max slot (5-cell non-max-suppression in `sag_detect.py`).
- **No change to the 2026-08-20 v0.2 inline `--min-component N` flag**
  in `code/wp1_detector/sag_detect.py`. The standalone skeleton is
  additive; the inline helper stays for backward-compat with the
  `f1_test_raw` audit field.
- **No change to score formulation** (depth × Frangi, the v0.5
  ceiling).
- **No change to the threshold-tuning algorithm** (v0.1 `tune_threshold()`
  on the calibration half).
- **No change to slope-mask logic** (v0.4 fixed-slope default 10°;
  v0.4 tuned via `--tune-slope`).
- **No change to the tier-A registry schema** — the CC filter cannot
  promote any candidate (no physics screen, no I12 confound check, no
  multi-evidence stacking; tier-A promotions remain a WP5 fusion
  concern, untouched here).

## Limitations / what's NOT in v0.2

- **The CC filter does NOT promote any tier-A candidate.** It is a
  post-processing step on the per-rung F1 metric and the
  `pred_<rung>m.tif` mask; it does not consume the registry schema,
  does not add a physics screen, does not check the I12 (Hapke / NAC
  sensor noise) confound, does not stack multi-evidence. A tier-A
  promotion still requires two-independent-methods agreement
  (registry schema, unchanged).
- **At `threshold = local_Amin`, the filter is a no-op on TRANQPIT1
  @ 5 m.** All four candidate peaks clear the 3-cell rung floor
  (component sizes 8, 66, 73, 215 cells). The headline v0.2 lift lives
  in `thr = 0` mode, not in the post-threshold path.
- **Not yet integrated into the full LLTB-1 v0.5 ladder pipeline.**
  The integration test is standalone (reads the WP2 score raster
  directly); the per-rung table is documented in `V0.2_PLAN.md` §4.1
  but not yet wired into `sag_detect.py` CLI plumbing. This is a
  documentation + test artefact, not a drop-in replacement for the
  inline `--min-component` flag.
- **Per-rung, not per-DTM.** The `area_min` table is global; per-DTM
  tuning (e.g., adjusting the 5 m floor for impact-melt terrain vs.
  mare) is v0.3 scope.

## Next steps (v0.3 candidates)

- **Integrate CC filter into the main ladder** (`sag_detect.py` CLI
  plumbing): wire the per-rung `area_min` table from
  `V0.2_PLAN.md` §4.1 behind a `--cc-area-min-table` flag, and
  expose `--cc-threshold` (default 0) alongside the existing
  `--min-component` flag. Apply CC filter post-score-render,
  pre-local-max in the same position as the inline
  `filter_small_components()` call.
- **Per-DTM `area_min` tuning.** The current per-rung table is
  global; per-DTM tuning (e.g., relaxing the 5 m floor on
  impact-melt terrain, tightening on flat mare) is the next
  precision-uplift axis. Test sites: Fieg_A 0.5 m (slope-dominated
  — should be a no-op), IndianTunnel_Collapse3 2 m (the 2026-08-20
  v0.2 regression rung), IndianTunnel_NorthSurface 2 m (cliff
  overhang).
- **Tier-A physics screen.** Wire the I12 (Hapke / NAC sensor noise)
  confound check into the candidate-promotion path so the CC
  filter's kill ratio can be translated into a true FP-rate
  reduction (the proxy is fine for the integration test, but a
  full F1 lift needs the physics screen).
- **Re-evaluate the v0.4 site table** with the integrated CC filter
  at `thr = 0`. The 2026-08-21 v0.4 release note's `slope_mask_tuned`
  field will become a per-rung `cc_thr_0_kill_ratio` audit field;
  the per-site F1 lift is the next honest number to publish.
